# AutoResponder (app)

Android-приложение: автоответчик на звонки, SMS и сообщения мессенджеров (RCS/WhatsApp/Telegram),
когда телефон «закрыт» — режим «Не беспокоить» (DND) или собственное расписание. Ответы генерирует
LLM с учётом базы знаний о компании, истории переписки и календаря праздников; при недоступности
LLM — офлайн-шаблон.

## Как это работает
- **Звонки** — держит роль `CALL_SCREENING`; в режиме «закрыто» отклоняет входящий (если номер
  подходит под маску страны) и шлёт авто-SMS. Отклонённый звонок пишется в журнал как
  пропущенный, а не как скрытый «заблокированный».
- **SMS** — принимает `SMS_RECEIVED`.
- **Мессенджеры/RCS** — через `NotificationListenerService`, ответ в тот же тред кнопкой Reply.
  Одно сообщение — ровно один ответ (дедуп по отправитель+текст). Собственные ответы, которые
  мессенджер дописывает обратно в уведомление, не принимаются за сообщения клиента.
- **Обработка только когда «закрыто»** — по системному DND и/или расписанию.
- **Очередь** — две FIFO-полосы (SMS/звонки и мессенджеры) обрабатываются последовательно,
  один адресат сериализован между полосами (без гонок и двойных ответов).

## Логика ответов (анти-флуд)
- До `Макс. ответов` (по умолчанию **6**) обычных авто-ответов на номер.
- Затем **одно системное предупреждение** (№ 7): «отвечает AI, живой человек ответит в рабочее
  время / через N часов, можно продолжать писать». Дальше — тишина до конца таймаута.
- Таймаут по умолчанию **60 минут**. Во время таймаута входящие **сохраняются** (для контекста),
  после таймаута авто-ответы возобновляются — сообщения не теряются.

## LLM
- Провайдеры: **Ollama** (в т.ч. Ollama Cloud `https://ollama.com` + ключ), OpenAI-совместимые,
  Claude, Gemini, DeepSeek. Основной + резервный канал.
- **Модель принадлежит провайдеру**: имя из Ollama (`gemma4:31b`) не существует в DeepSeek или
  OpenAI. При смене провайдера поле модели очищается — нажмите «Запросить все модели» и выберите
  из списка. Ошибка API (нет такой модели, неверный ключ) пишется в журнал, а не превращается
  молча в офлайн-шаблон.
- **Режим размышления (reasoning)** — тумблер. Выкл (по умолчанию): прямой краткий ответ, быстрый
  фолбэк ~13с (подходит всем, включая DeepSeek с `think:false`). Вкл: модель думает (бюджет токенов
  большой, таймаут до 95с), итоговый ответ всё равно обрезается под лимит SMS.
- LLM активна только при включённом тумблере и заполненном ключе; иначе — офлайн-шаблон.
- Контекст: в промпт подаётся недавняя переписка по адресату из локальной БД истории.
- Текущие дата/время/день недели с устройства передаются модели — праздники накладываются на
  текущий год, корректно понимаются «сегодня/завтра/в субботу».

## Файл «О компании» (.md) — база знаний для LLM
Описывает компанию, услуги, часы, ссылки на запись и т.п. Два способа задать:
1. **Через приложение** — «Загрузить .md» (копия хранится внутри приложения).
2. **По пути** — положить файл в `/sdcard/AutoResponder/about.md`.

Приоритет: загруженная копия → `/sdcard/AutoResponder/about.md` → поле «Факты о компании».
Обычный Markdown/текст. Пример — `holidays/about-bigtweak.md` в этом репозитории.

## Список праздников (гос. выходные)
Отдельный **загружаемый** список + тумблер «Учитывать праздники» (по умолчанию **выключен**,
список пуст). Когда включён — LLM знает даты, когда офис закрыт (приём только по договорённости),
и сверяет их с текущей датой устройства.

Источник: загруженная копия (в приложении) → `/sdcard/AutoResponder/holidays.txt`.

**Формат файла** (одна запись в строке; `#` и пустые строки игнорируются):
```
# ежегодно (каждый год):
MM-DD Название
# конкретная дата (напр. подвижная Пасха):
YYYY-MM-DD Название
```
Пример:
```
01-01 Новый год
12-25 Рождество
2026-04-06 Пасхальный понедельник
```
Готовые списки в каталоге [`holidays/`](holidays/): `holidays-cz.txt`, `holidays-ru.txt`,
`holidays-ua.txt` — только государственные нерабочие дни.

## Избранные (кому НЕ отвечать автоматически)
- **По номеру** (звонки, SMS, RCS) — список номеров + добавление из контактов; плюс
  «звёздные»/все контакты книги.
- **Мессенджеры (WhatsApp, Telegram)** — отдельный список: имя из телефонной книги, номер
  или маска, плюс кнопка **«Импортировать избранные контакты из книги»**.

### Что мессенджер реально кладёт в уведомление
`@username` там нет — вообще. WhatsApp и Telegram подставляют **имя, под которым человек
записан в вашей телефонной книге** («Пётр Новак»). Если контакта в книге нет —
Telegram покажет имя из профиля собеседника, WhatsApp — номер в собственном формате
(«+7 900 123-45-67»). Поэтому запись вида `ivan_novak` не совпадёт никогда.

Точную строку видно в журнале (`NOTIF[telegram] from='…'`) и в истории переписки.

Отсюда же и кнопка импорта: она забирает **имена** звёздных (избранных) контактов — ровно те
строки, которые придут в уведомлении.

Переключатели «не отвечать звёздным / всем контактам из книги» действуют и на мессенджеры:
контакт ищется по имени из уведомления (точное совпадение, без учёта регистра).

### Маски
В обоих списках запись может быть маской: `*` — любой отрезок текста, `?` — один символ.
Маска проверяется и по исходной строке, и по одним цифрам, так что формат номера не мешает:

| Запись | Совпадёт с |
|---|---|
| `Мама*` | `Мама Прага` |
| `+420*` | `+420 777 123 456` |
| `*4567` | `+7 900 123-45-67` |
| `Иван ?.` | `Иван П.` |

Без маски: имена сравниваются без учёта регистра и префикса `@`, номера — по последним
9 цифрам, поэтому формат записи не важен (`+31612345678`, `31612345678`, `+31 6 1234 5678`).
Под каждой записью списка подписано, как она будет сопоставляться.

**Номер приводится к каноническому виду при сохранении** — и в «Избранных», и в чёрном списке,
и при добавлении из книги контактов: пробелы, скобки и дефисы убираются, `00` меняется на `+`,
а если код страны есть, но `+` не написали — он дописывается сам
(`420 608 210 867` → `+420608210867`, `(420) 608-210-867` → `+420608210867`,
`00420608210867` → `+420608210867`). Под полем ввода видно, что именно сохранится.
Местный номер без кода страны (`608 210 867`, `0612345678`) `+` не получает — иначе вышел бы
несуществующий международный номер; на сопоставление это не влияет, оно идёт по цифрам.
**Маски не трогаются вообще** (`+420*` остаётся как есть): маска сравнивается и с исходной
строкой, поэтому её формат менять нельзя.

## Чёрный список

Отдельный экран: кому отвечать не по общим правилам. Запись — номер, имя из телефонной книги
или маска (`*` — любой текст, `?` — один символ), сопоставление то же, что в «Избранных».

**Не зависит от режима.** Общий автоответ уходит только когда «закрыто» (DND или расписание);
запись из ЧС срабатывает и в рабочее время. Текущий режим передаётся в промпт, чтобы LLM
выбрала тон. Маску стран и «Избранных» ЧС обходит — во всех каналах одинаково (звонки, SMS,
RCS, мессенджеры).

**Но подчиняется:** главному тумблеру, переключателям «отвечать на звонки / на SMS», паузе
автоответа и лимиту ответов (`maxReplies` + таймаут) — после лимита наступает тишина, как и для
обычных контактов.

Настройки записи:

| Настройка | Смысл |
|---|---|
| Отвечать через LLM | выключено (по умолчанию) — тишина; включено — ответ своим промптом |
| SMS / Мессенджеры | в каких каналах отвечать |
| Звонки: пропускать | звонок проходит как обычно (по умолчанию) |
| Звонки: отклонять + SMS | звонок отклоняется, уходит SMS по отдельному «промпту звонка» |
| Срок блокировки | навсегда (по умолчанию), 1 час, 3 часа, 1 день или «до даты» |

**Срок блокировки.** Выбирается сразу при добавлении (чипы под полем ввода — они же действуют
для кнопки «Добавить из контактов») и меняется потом у каждой записи. Пресеты отсчитываются от
момента добавления; «Дата…» открывает календарь и блокирует до конца выбранного дня (23:59).
Когда срок вышел, запись перестаёт срабатывать (звонки и сообщения снова идут по общим
правилам), в списке помечается «Срок истёк» и убирается кнопкой «Удалить истёкшие» — сама она
не удаляется, чтобы можно было продлить.

Попытки связи копятся и приходят сводным уведомлением: выключено / через N минут / раз в день
в заданное время.

## Утренняя сводка и «Требуют ответа»

Автоответ закрывает разговор только по форме: клиенту обещано, что ответят в рабочее время,
и это обещание кто-то должен выполнить. Раньше список таких людей приходилось восстанавливать
по памяти, листая историю.

**Экран «Требуют ответа»** — ветки, где **за вас ответил робот**, а живого ответа не было.
Отбор идёт по авто-ответам, а не по входящим: банковские рассылки, переписка с родными и
всё, на что автоответчик не отвечал, сюда не попадают — это шум, из-за которого список
перестают открывать.

Авто-ответ ответом не считается: он и есть причина, по которой ветка в списке. Засчитывается
только наше исходящее, сделанное руками, — отправленная SMS или исходящий звонок из журнала.
Ветка уходит сама, как только вы ответили; кнопка «Готово» убирает её вручную (клиент
напишет снова — вернётся). Рядом кнопки «Позвонить», «SMS» и «В ЧС».

**Сводка** приходит раз в сутки в заданный час (по умолчанию **8:00**): сколько было звонков
и сообщений, сколько ответил робот, кому вы ещё не ответили сами. Ночью не приходит — в этом
и смысл. Alarm пере-взводится после срабатывания и после перезагрузки.

## Тихий час (ночные SMS)

Звонок ночью отклоняется как обычно, но **ответная SMS придерживается до утра** — и одна на
номер, сколько бы раз ни звонили. Набравший в три часа ночи чаще всего ошибся номером или
звонит из другого часового пояса; ответная SMS будит его в ту же секунду.

По умолчанию выключено; окно задаётся (по умолчанию 22:00–08:00) и переходит через полночь.
На ответы по SMS и в мессенджерах не влияет: человек написал сам, молчание выглядело бы
поломкой.

## Прайс-лист (цены как факты)

Тот же принцип, что и в разговоре о статусе заказа: **цифры даёт код, модель только оформляет
фразу**. Придуманная моделью цена — это спор с клиентом на пороге и работа себе в убыток.

Файл CSV: `устройство;услуга;цена;срок`, `#` — комментарий, заголовок распознаётся сам.
Источник: загруженная через приложение копия → `/sdcard/AutoResponder/prices.csv`.

```
iPhone 12;замена экрана;3500 Kč;1 день
MacBook Pro 14;замена батареи;5900 Kč;2 дня
```

Когда клиент спрашивает про деньги, в промпт уходят подходящие строки и запрет называть
что-либо сверх них. **Если подходящей строки нет, блок уходит всё равно** — с требованием
сказать, что цену подтвердит мастер после диагностики. Без этого модель охотно придумает
«примерно 2000 Kč». Прайс не задан — цены не называются вовсе.

## Управление по SMS

Телефон лежит в мастерской, а выключить автоответ иногда нужно немедленно и не с него.
Команды принимаются **только с номеров из явного списка** и только когда функция включена
(по умолчанию **выключена**: отправителя SMS подделать несложно).

| Команда | Что делает |
|---|---|
| `STATUS` / `статус` | вкл/выкл, режим, счётчики за сутки, сколько требует ответа |
| `OFF` / `выкл` | выключить автоответ |
| `ON` / `вкл` | включить |
| `PAUSE` / `пауза` | пауза до следующего включения DND |
| `DIGEST` / `сводка` | показать сводку на телефоне |

Ответ уходит SMS на тот же номер и с той же карты. Команда не попадает ни в историю,
ни в контекст LLM, ни в лимиты — это не переписка с клиентом.

## Контекст переписки (что уходит в LLM)
В промпт подставляются **последние 12 сообщений** ветки — из локальной БД истории, а не из
уведомления. Строки журнала звонков («входящий звонок», «исходящий звонок (717с)») в это окно
не попадают: вместо них одна строка «клиент звонил N раз за 7 дней». Текущее входящее не
дублируется — оно уходит отдельным полем.

### Один человек — один контекст
История хранится по ключам, и ключ у каналов разный:

| Канал | Ключ ветки |
|---|---|
| звонки, SMS, RCS | нормализованный номер |
| WhatsApp, Telegram | имя отправителя из уведомления |

Перед сборкой промпта ключи **склеиваются по человеку** через телефонную книгу: имя ↔ все
номера контакта (у контакта их может быть несколько — рабочий, мобильный). Номер, записанный
по-разному («+420777123456» из SMS и «+420 777 123 456» из WhatsApp), сводится по цифрам.
В итоге клиент, который позвонил, потом написал в WhatsApp, а потом прислал SMS, для LLM
остаётся одним человеком с одной историей.

Если контакта в книге нет, склеивать не по чему — ветка остаётся одна, по той строке, что
пришла.

В журнале видно, что реально ушло:
`Контекст[Пётр Новак]: 12 сообщ. + звонков за 7д: 3; ветки: Пётр Новак | +420777123456`

Экран «История общения» по-прежнему показывает ветки раздельно — склейка сделана для контекста
LLM, не для списка переписок.

## Бэкап базы истории
БД истории — источник контекста для LLM. Ежедневный бэкап (планировщик в приложении) в
`/sdcard/AutoResponder/backups` с ротацией (по умолчанию **10** копий), выбор часа, кнопка
«Сделать бэкап сейчас» и **восстановление** из списка копий.

## SIM и маска стран
Каждая карта включается отдельным тумблером и имеет **свой список префиксов**; рядом показано,
что за карта реально стоит в слоте (имя из системы, при заглушке вида «SIM1» — оператор).

- Номеру отвечаем, если он попал в список **включённой** карты.
- Отвечает та карта, чьё правило **точнее**: `+420` выигрывает у `+4`.
- Один и тот же префикс в обоих списках — интерфейс подсвечивает конфликт, такие номера уходят
  с карты по умолчанию (порядок полей ни на что не влияет).
- Номера вне правил обслуживает **SIM по умолчанию**; выключенную карту выбрать нельзя.

Режим выбора SIM ручной: определение карты, на которую пришёл вызов, на части прошивок
недостоверно, поэтому входящий `subId` остаётся только в журнале как справочная информация.

## Журнал и диагностика
Журнал живёт в оперативной памяти и виден в разделе «Журнал».
В него попадают: выбранная SIM и правило, по которому она выбрана; причина, по которой
уведомление отброшено; причина ответа офлайн-шаблоном (LLM выключена, нет сети, не задана
модель или ключ); текст ошибки API. Те же строки дублируются в системный лог —
`adb logcat -s AutoResp`.

**Копия в файл** (по умолчанию включена): `/sdcard/AutoResponder/logs/autoresp-ГГГГ-ММ-ДД.log`,
по файлу на сутки, хранится 7 дней, старые удаляются сами. В памяти журнал живёт до
перезагрузки, а разбираться приходится через сутки: «почему клиенту не ответили вчера
вечером» по пустому буферу не разобрать. Запись асинхронная, любая ошибка файловой системы
игнорируется — журнал не должен мешать работе.

**Heartbeat.** Раз в 10 минут приложение трогает `files/heartbeat` в своём каталоге.
KernelSU-модуль смотрит на время изменения: файл устарел на полчаса — процесс убит менеджером
питания, и модуль пере-привязывает слушателя уведомлений, поднимая приложение заново. При
`force-stop` система снимает и alarm'ы, поэтому файл перестаёт обновляться сам собой — ровно
то поведение, которое нужно.

## Приватность
- Резервное копирование Android для приложения отключено (`allowBackup=false`) — настройки с
  ключами не уезжают в облако.
- Экспорт настроек по умолчанию **без API-ключей**; отдельный тумблер включает их выгрузку для
  переноса на своё устройство. Импорт файла без ключей не стирает уже введённые.

## Доступ к файлам
Чтение/запись `/sdcard/AutoResponder` требует all-files access (`MANAGE_EXTERNAL_STORAGE`) —
грант выдаёт KernelSU-модуль автоматически (`appops`).

## Сборка
- `.github/workflows/build.yml` — сборка на push в **любую** ветку: юнит-тесты, затем
  release и debug APK. Локально Android SDK есть не всегда, и ветка — единственная проверка.
- Юнит-тесты (`./gradlew testDebugUnitTest`) закрывают правила, где ошибка не видна снаружи:
  сопоставление номеров и масок, канонический вид номера, расписание с переходом через
  полночь, тихий час, бюджет SMS-сегментов, определение языка, дедуп, срок в чёрном списке,
  распознавание вопроса о статусе и о цене, разбор SMS-команд. Цена ошибки в них — молчание
  для живого клиента, которое замечают только по жалобе.
- `.github/workflows/release.yml` — release APK при теге `v*` (в Releases).

Локально: `./gradlew assembleRelease` (нужен Android SDK + JDK 17; для release-подписи —
env `KEYSTORE_FILE`/`KEYSTORE_PASSWORD`/`KEY_ALIAS`, иначе debug-подпись).

## Установка
Через KernelSU-модуль (рекомендуется): ставит APK, выдаёт права, назначает роль `CALL_SCREENING`,
включает доступ к уведомлениям, добавляет в Doze whitelist, выдаёт доступ к файлам, самообновляется.
Модуль: https://github.com/davnozdu/autoresponder-ksu-module
