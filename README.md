# AutoResponder (app)

Android-приложение: автоответчик на звонки, SMS и сообщения мессенджеров (RCS/WhatsApp/Telegram),
когда телефон «закрыт» — режим «Не беспокоить» (DND) или собственное расписание. Ответы генерирует
LLM с учётом базы знаний о компании, истории переписки и календаря праздников; при недоступности
LLM — офлайн-шаблон.

## Как это работает
- **Звонки** — держит роль `CALL_SCREENING`; в режиме «закрыто» отклоняет входящий (если номер
  подходит под маску страны) и шлёт авто-SMS. Отклонённый звонок пишется в журнал как
  пропущенный, а не как скрытый «заблокированный».
- **SMS** — принимает `SMS_RECEIVED`.
- **Мессенджеры/RCS** — через `NotificationListenerService`, ответ в тот же тред кнопкой Reply.
  Одно сообщение — ровно один ответ (дедуп по отправитель+текст). Собственные ответы, которые
  мессенджер дописывает обратно в уведомление, не принимаются за сообщения клиента.
- **Обработка только когда «закрыто»** — по системному DND и/или расписанию.
- **Очередь** — две FIFO-полосы (SMS/звонки и мессенджеры) обрабатываются последовательно,
  один адресат сериализован между полосами (без гонок и двойных ответов).

## Логика ответов (анти-флуд)
- До `Макс. ответов` (по умолчанию **6**) обычных авто-ответов на номер.
- Затем **одно системное предупреждение** (№ 7): «отвечает AI, живой человек ответит в рабочее
  время / через N часов, можно продолжать писать». Дальше — тишина до конца таймаута.
- Таймаут по умолчанию **60 минут**. Во время таймаута входящие **сохраняются** (для контекста),
  после таймаута авто-ответы возобновляются — сообщения не теряются.

## LLM
- Провайдеры: **Ollama** (в т.ч. Ollama Cloud `https://ollama.com` + ключ), OpenAI-совместимые,
  Claude, Gemini, DeepSeek. Основной + резервный канал.
- **Модель принадлежит провайдеру**: имя из Ollama (`gemma4:31b`) не существует в DeepSeek или
  OpenAI. При смене провайдера поле модели очищается — нажмите «Запросить все модели» и выберите
  из списка. Ошибка API (нет такой модели, неверный ключ) пишется в журнал, а не превращается
  молча в офлайн-шаблон.
- **Режим размышления (reasoning)** — тумблер. Выкл (по умолчанию): прямой краткий ответ, быстрый
  фолбэк ~13с (подходит всем, включая DeepSeek с `think:false`). Вкл: модель думает (бюджет токенов
  большой, таймаут до 95с), итоговый ответ всё равно обрезается под лимит SMS.
- LLM активна только при включённом тумблере и заполненном ключе; иначе — офлайн-шаблон.
- Контекст: в промпт подаётся недавняя переписка по адресату из локальной БД истории.
- Текущие дата/время/день недели с устройства передаются модели — праздники накладываются на
  текущий год, корректно понимаются «сегодня/завтра/в субботу».

## Файл «О компании» (.md) — база знаний для LLM
Описывает компанию, услуги, часы, ссылки на запись и т.п. Два способа задать:
1. **Через приложение** — «Загрузить .md» (копия хранится внутри приложения).
2. **По пути** — положить файл в `/sdcard/AutoResponder/about.md`.

Приоритет: загруженная копия → `/sdcard/AutoResponder/about.md` → поле «Факты о компании».
Обычный Markdown/текст. Пример — `holidays/about-bigtweak.md` в этом репозитории.

## Список праздников (гос. выходные)
Отдельный **загружаемый** список + тумблер «Учитывать праздники» (по умолчанию **выключен**,
список пуст). Когда включён — LLM знает даты, когда офис закрыт (приём только по договорённости),
и сверяет их с текущей датой устройства.

Источник: загруженная копия (в приложении) → `/sdcard/AutoResponder/holidays.txt`.

**Формат файла** (одна запись в строке; `#` и пустые строки игнорируются):
```
# ежегодно (каждый год):
MM-DD Название
# конкретная дата (напр. подвижная Пасха):
YYYY-MM-DD Название
```
Пример:
```
01-01 Новый год
12-25 Рождество
2026-04-06 Пасхальный понедельник
```
Готовые списки в каталоге [`holidays/`](holidays/): `holidays-cz.txt`, `holidays-ru.txt`,
`holidays-ua.txt` — только государственные нерабочие дни.

## Избранные (кому НЕ отвечать автоматически)
- **По номеру** (звонки, SMS, RCS) — список номеров + добавление из контактов; плюс
  «звёздные»/все контакты книги.
- **Мессенджеры (WhatsApp, Telegram)** — отдельный список: имя из телефонной книги, номер
  или маска, плюс кнопка **«Импортировать избранные контакты из книги»**.

### Что мессенджер реально кладёт в уведомление
`@username` там нет — вообще. WhatsApp и Telegram подставляют **имя, под которым человек
записан в вашей телефонной книге** («Алекс Лапшинский»). Если контакта в книге нет —
Telegram покажет имя из профиля собеседника, WhatsApp — номер в собственном формате
(«+7 951 457-28-49»). Поэтому запись вида `glen300` не совпадёт никогда.

Точную строку видно в журнале (`NOTIF[telegram] from='…'`) и в истории переписки.

Отсюда же и кнопка импорта: она забирает **имена** звёздных (избранных) контактов — ровно те
строки, которые придут в уведомлении.

Переключатели «не отвечать звёздным / всем контактам из книги» действуют и на мессенджеры:
контакт ищется по имени из уведомления (точное совпадение, без учёта регистра).

### Маски
В обоих списках запись может быть маской: `*` — любой отрезок текста, `?` — один символ.
Маска проверяется и по исходной строке, и по одним цифрам, так что формат номера не мешает:

| Запись | Совпадёт с |
|---|---|
| `Мама*` | `Мама Нидерланды` |
| `+420*` | `+420 777 123 456` |
| `*2849` | `+7 951 457-28-49` |
| `Иван ?.` | `Иван П.` |

Без маски: имена сравниваются без учёта регистра и префикса `@`, номера — по последним
9 цифрам, поэтому формат записи не важен (`+31615092866`, `31615092866`, `+31 615 092 866`).
Под каждой записью списка подписано, как она будет сопоставляться.

## Бэкап базы истории
БД истории — источник контекста для LLM. Ежедневный бэкап (планировщик в приложении) в
`/sdcard/AutoResponder/backups` с ротацией (по умолчанию **10** копий), выбор часа, кнопка
«Сделать бэкап сейчас» и **восстановление** из списка копий.

## SIM и маска стран
Каждая карта включается отдельным тумблером и имеет **свой список префиксов**; рядом показано,
что за карта реально стоит в слоте (имя из системы, при заглушке вида «SIM1» — оператор).

- Номеру отвечаем, если он попал в список **включённой** карты.
- Отвечает та карта, чьё правило **точнее**: `+420` выигрывает у `+4`.
- Один и тот же префикс в обоих списках — интерфейс подсвечивает конфликт, такие номера уходят
  с карты по умолчанию (порядок полей ни на что не влияет).
- Номера вне правил обслуживает **SIM по умолчанию**; выключенную карту выбрать нельзя.

Режим выбора SIM ручной: определение карты, на которую пришёл вызов, на части прошивок
недостоверно, поэтому входящий `subId` остаётся только в журнале как справочная информация.

## Журнал и диагностика
Журнал живёт в оперативной памяти (ничего не пишется во flash) и виден в разделе «Журнал».
В него попадают: выбранная SIM и правило, по которому она выбрана; причина, по которой
уведомление отброшено; причина ответа офлайн-шаблоном (LLM выключена, нет сети, не задана
модель или ключ); текст ошибки API. Те же строки дублируются в системный лог —
`adb logcat -s AutoResp`.

## Приватность
- Резервное копирование Android для приложения отключено (`allowBackup=false`) — настройки с
  ключами не уезжают в облако.
- Экспорт настроек по умолчанию **без API-ключей**; отдельный тумблер включает их выгрузку для
  переноса на своё устройство. Импорт файла без ключей не стирает уже введённые.

## Доступ к файлам
Чтение/запись `/sdcard/AutoResponder` требует all-files access (`MANAGE_EXTERNAL_STORAGE`) —
грант выдаёт KernelSU-модуль автоматически (`appops`).

## Сборка
- `.github/workflows/build.yml` — сборка на каждый push в `main` (проверка компиляции).
- `.github/workflows/release.yml` — release APK при теге `v*` (в Releases).

Локально: `./gradlew assembleRelease` (нужен Android SDK + JDK 17; для release-подписи —
env `KEYSTORE_FILE`/`KEYSTORE_PASSWORD`/`KEY_ALIAS`, иначе debug-подпись).

## Установка
Через KernelSU-модуль (рекомендуется): ставит APK, выдаёт права, назначает роль `CALL_SCREENING`,
включает доступ к уведомлениям, добавляет в Doze whitelist, выдаёт доступ к файлам, самообновляется.
Модуль: https://github.com/davnozdu/autoresponder-ksu-module
