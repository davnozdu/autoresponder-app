# Контекст для LLM: запись звонков мессенджеров

Состояние исследования на 2026-09-29. Это описание проверенного поведения и следующего направления, **не свидетельство того, что отказ от overlay уже реализован**. Перед работой сверяйте текущий код, состояние устройства и ветку. Смежный репозиторий: `../autoresponder-ksu-module` (при отдельном клонировании: `davnozdu/autoresponder-ksu-module`).

Пользователь исключил из этой задачи разделение голосов «я/вы», метки важных моментов, поиск важных фраз и переход к их месту в записи. Не предлагайте и не добавляйте эти функции в рамках миграции без overlay. Приоритет — надёжная запись обеих сторон, малый расход батареи и автономность основного модуля.

## Что уже работает на устройстве

- Устройство: OnePlus 15 CPH2745IN, OxygenOS / Android 16, KernelSU Next. Приложение `com.davnozdu.autoresponder`.
- Модуль запускает `MsgrShellHost` через `app_process` под UID `shell` (2000). Хост заранее регистрирует `AudioPolicy` с `ROUTE_FLAG_LOOP_BACK_RENDER`; дальняя сторона поступает через `REMOTE_SUBMIX`, ближняя — через `MIC`. Между звонками хост блокируется на локальном сокете, не читает микрофон и не опрашивает систему.
- На реальных звонках WhatsApp Business и Telegram получены файлы с ненулевыми отсчётами обеих сторон. В прошлом попытка захвата MIC из UID приложения давала цифровую тишину даже при статусе priv-app и foreground-службе; под UID 2000 `MIC silenced:false`.
- Политика захвата должна быть зарегистрирована **до создания аудиопотока звонка**. Позднее подключение sink допустимо; поздняя регистрация политики может оставить дальнюю сторону немой на весь звонок.
- Текущая запись, IPC, журнал и восстановление готовых WAV реализованы в `app/src/main/java/com/davnozdu/autoresponder/msgrec/`. Не заменяйте работающий путь предположением о разрешениях root/UID 0: аудиосистема проверялась именно с UID 2000.

## Зачем сейчас установлен overlay

- `MsgrCaptureManager` уже использует публичный `AudioManager.OnModeChangedListener` и `MODE_IN_COMMUNICATION` для окна звонка. Окончание дебаунсится примерно 2,5 с: при коротком провале режима преждевременное закрытие и повторное открытие sink нарушало маршрут дальнего звука.
- Для определения **какой именно мессенджер** звонит приложение пока вызывает `AudioPlaybackConfiguration.getClientUid` на активном `USAGE_VOICE_COMMUNICATION` плеере. Android обезличивает UID для обычного приложения. Здесь нужен `MODIFY_AUDIO_ROUTING`, полученный через `system/priv-app` + allowlist. Два других signature|privileged разрешения нужны были для захвата из приложения, но фактический захват теперь принадлежит shell-хосту.
- На KernelSU Next этой прошивки каталог `system/` модуля накладывается только при установленном отдельном метамодуле `meta-overlayfs`. **Цель исследования — убрать зависимость от `meta-overlayfs`, сохранив основной KSU-модуль.** Основной модуль по-прежнему нужен для запуска shell-хоста, роли call screening, runtime-разрешений, NotificationListener, watchdog, bridge и бэкапов. «Убрать overlay» не означает «удалить весь KSU-модуль».
- Поиск по репозиториям на дату исследования не нашёл другой функциональной зависимости приложения от этих трёх privileged-разрешений. Перед удалением `/system/priv-app` проверьте это снова; manifest, installer и документация пока описывают старую схему.

## Кандидат на работу без overlay (ещё не проверен end-to-end)

1. Оставить публичный событийный сигнал `MODE_IN_COMMUNICATION` в живущем `NotifListenerService` приложения. Дополнительный постоянный процесс и polling не нужны.
2. По событию запросить у уже работающего shell-хоста UID владельца звонка. У CallVault (`server/VoipAppIdentity.kt`) сначала используется список активных playback-конфигураций через `IAudioService`, затем fallback по `dumpsys audio`: владелец аудиорежима и активный `USAGE_VOICE_COMMUNICATION` плеер. Это важнее догадки по уведомлению. На OnePlus 15 `dumpsys audio` уже показывал пакеты и UID WhatsApp/Telegram в истории потоков; своевременный ответ при начале **нового** звонка ещё надо подтвердить.
3. Учитывать гонку: режим может смениться раньше появления voice-плеера. CallVault ограниченно повторяет поиск (около 1,2 с с шагом 150 мс). Отбрасывать системные UID `<10000`, проверять активный voice-плеер и сопоставлять UID с разрешёнными пакетами через `PackageManager`. Уведомление использовать только для имени собеседника, с привязкой к уже установленному пакету.
4. `MODE_IN_COMMUNICATION` сам по себе не доказывает звонок мессенджера: IMS/VoLTE/VoWiFi могут пересекаться с этим режимом. Для отсечения сотового звонка CallVault применяет `TelecomManager.isInManagedCall`; не подменять это `TelephonyManager.callState`, который учитывает также self-managed вызовы. Сохранить дебаунс окончания и не пересоздавать sink на коротком провале режима.
5. Shell-хост продолжает регистрировать AudioPolicy до звонка и захватывать обе стороны под UID 2000. Сокет проверяет UID клиента. После подтверждения механизма приложение может остаться обычным `/data`-приложением; модуль сможет ставить APK и выдавать обычные runtime-разрешения без `system/` overlay.

## Проверка перед отказом от meta-overlayfs

- Сначала проверить новый UID-резолвер «в тени» текущей записи: сравнить пакет и UID для входящих/исходящих WhatsApp и Telegram, звонка с SIM, повторного звонка и звонка после перезагрузки. Проверить короткие провалы режима, экран блокировки и маршруты гарнитуры по необходимости.
- Проверить, что старт происходит до/во время появления voice-плеера, нет дублей, у собеседника не пропадает звук, итоговый WAV имеет корректную длительность и ненулевые `mic`/`far`, запись появляется в журнале.
- Только затем собрать вариант модуля без `system/priv-app`, privapp-XML и hiddenapi-sysconfig, установить и перезагрузить. Убедиться, что `/data`-приложение работает без флага `PRIVILEGED`, хост и AudioPolicy стартуют, разрешения и другие функции модуля сохранились. Данные приложения не удалять. `meta-overlayfs` удалять отдельно после проверки, не нужен ли он другим модулям.
- Держать проверенный вариант с overlay как путь возврата, пока несколько настоящих звонков без overlay не подтвердят работу.
