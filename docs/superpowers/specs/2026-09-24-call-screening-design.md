# Скрининг звонков (v0.21.0) — дизайн

## Цель

Во время специально настроенного «рабочего времени» (своё расписание, независимое от
существующего расписания «закрыто») входящий звонок не от избранного контакта:
телефон отвечает сам, проигрывает абоненту приветствие на одном из трёх языков, затем
повторяющийся зуммер (пока абонент ждёт), и пишет разговор с самого начала. Владелец в
это время видит на ЯРКОМ экране карточку с данными о звонящем (если есть CRM) и две
кнопки — «Принять» (подключиться к уже идущему звонку) и «Отклонить» (положить трубку).
Никакого повторного взаимодействия со звонилкой не требуется — звонок с точки зрения
Android активен всё это время, кнопки просто переключают участие владельца.

## Почему это отдельная фича, а не расширение существующих

- **Не то же самое, что «гарнитура»**: та фича — тихая, для сценария «иду, не хочу
  ничего видеть/слышать». Эта — наоборот, видимая и интерактивная, для сценария «я на
  месте, хочу посмотреть кто звонит и решить». Оба сценария используют один и тот же
  избранный-скип (`SkipPolicy`), но разное поведение экрана/звука.
- **Не то же самое, что «закрыто»**: у «закрыто» уже два режима (SMS-отказ / тихий
  автоответчик), оба без участия владельца в моменте. Здесь владелец активно решает
  прямо во время звонка.

## Маршрутизация (`CallScreeningServiceImpl.onScreenCall`)

Новый порядок проверок (жирным — новое):

```
1. ЧС (blacklist)                                         → автоответчик, как сейчас
2. **Скрининг активен (своё расписание) + не избранный**    → НОВОЕ: интерактивный скрининг
3. Гарнитура подключена + не избранный                     → тихий автоответчик, как сейчас
4. «Закрыто» (существующее расписание/DND) + маска + !skip  → как сейчас (SMS/голос)
5. иначе                                                    → звонит нормально
```

**Скрининг проверяется РАНЬШЕ гарнитуры** (изменено по итогам ревью): в рабочее время
даже с подключёнными наушниками (например, за рулём) владелец хочет видеть карточку и
решать сам — «мог бы ответить на звонок с телефона». Тихий режим гарнитуры остаётся
приоритетным только ВНЕ часов скрининга (или когда скрининг выключен).

`headsetTrigger`/`screeningTrigger` оба используют один и тот же `skip` (избранные),
вычисленный один раз выше в функции — без дублирования `SkipPolicy.reason`.

## Новый модуль: `ScreeningPolicy`

Зеркалит `ClosedState`/`closedBySchedule`: чистая функция без `Context`, только числа —
для юнит-теста (окно через полночь, совпадающие границы — как у существующего теста
расписания).

```kotlin
object ScreeningPolicy {
    fun isActive(context: Context, s: Settings): Boolean =
        s.screeningEnabled && inWindow(s)   // inWindow — чистая, как closedBySchedule
}
```

## Новые настройки (`Settings.kt`)

Собственное расписание, независимое от существующего `work_days`/`sched_start`/`sched_end`:

```kotlin
var screeningEnabled: Boolean        // default false
var screeningWorkDaysMask: Int       // default = workDaysMask (пн-пт), свой ключ
var screeningStartMin: Int           // default 9*60
var screeningEndMin: Int             // default 18*60
```

Язык приветствия по умолчанию для скрининга — независим от существующего `amGreetingLang`
(тот используется для ЧС/закрыто, там значение по умолчанию — «авто»/пусто):

```kotlin
var screeningDefaultLang: String     // default "cs" — все звонки по умолчанию слышат чешский
```

Библиотека приветствий, по одному слоту на язык (`cs`/`ru`/`en`), каждый — файл ИЛИ
TTS-текст (зеркалит существующую пару `amGreetingSource`/`amGreetingFile`/`amGreetingText`,
просто ×3 с суффиксом языка):

```kotlin
var screeningGreetingSourceCs: Int   // 0 = TTS, 1 = файл; default 0
var screeningGreetingFileCs: String
var screeningGreetingTextCs: String  // default = Settings.DEF_AM_GREETING на чешском

// то же для Ru и En
```

## Приветствие + повторяющийся зуммер (`Greeting.kt`)

Новая функция `prepareScreening(ctx, langSlot): String?` — почти как существующий
`prepare()`, но:

1. Источник (файл/TTS) берётся из `screeningGreetingSource<Lang>` вместо `amGreetingSource`.
2. После речи дописывается НЕ один `beepTailPcm()`, а серия — в цикле, на всю
   `amMaxMessageSec` (тот же лимит, что и у обычного автоответчика). Один и тот же
   генератор бипа (`beepTailPcm()`), просто вызывается N раз вместо одного — без второго
   `play()`-вызова и без отслеживания «когда доиграло первое» (в протоколе демона такого
   события нет, поэтому не пытаемся на него полагаться).
3. Обрывается мгновенно штатным `AmBridge.stop()` при «Принять»/«Отклонить»/отбое —
   ничего нового в протоколе демона не требуется.

Кэшируется так же, как обычное приветствие (`greeting-<hash>.pcm`), ключ включает язык и
источник — кросс-протухания не будет по той же логике, что уже есть.

## UI: `CallerOverlay` + новые кнопки

- `actions()` получает новый параметр `showAcceptDecline: Boolean`. Сейчас блок кнопок
  целиком скрыт без данных CRM (`if (lookup != null && lookup.records.isNotEmpty())`) —
  это условие остаётся ТОЛЬКО для CRM-кнопок («Статус по SMS»/«Отвечаю я»); «Принять»/
  «Отклонить» показываются всегда, когда `showAcceptDecline=true`, независимо от CRM.
- Вызывается из `AnswerMachineService.runFlow` для нового `reason="screening"`, ВМЕСТО
  `AmBlockOverlay` — без гашения подсветки (`AmBridge.blockOn`/`redim`/`blockOff` не
  вызываются в этой ветке) и без инхибита тача. Экран ведёт себя как при обычном звонке:
  ярко, интерактивно.
- Владелец остаётся заглушён (`ADJUST_MUTE`, как у обычного автоответчика) пока не
  нажмёт «Принять» — карточка видна, но живого звука абонента по умолчанию не слышно,
  чтобы решение принималось по CRM-карточке/номеру, а не по подслушиванию вслепую.
  **Если нужно иначе (слышать абонента сразу, пока карточка висит) — отдельно скажи,
  это меняет пункт 2 ниже.**
- «Принять»: `am.adjustStreamVolume(STREAM_VOICE_CALL, ADJUST_UNMUTE, 0)` +
  `am.isMicrophoneMute = false` + `AmBridge.stop()` (обрывает зуммер) + скрыть карточку.
  Звонок не пересоединяется — он был активен всё это время.
- «Отклонить»: существующий `endCall()`.

## Запись

Уже стартует ДО приветствия в текущем `runFlow` (`AmBridge.recStart` вызывается раньше
`AmBridge.play`) — отдельно делать нечего, пункт «пишется сразу с приветствия» уже
выполняется архитектурно для ЛЮБОЙ причины автоответчика, включая новую `"screening"`.

## Новый UI в `MainActivity`

- Новая `ExpandableSection("Скрининг звонков")`: тумблер `screeningEnabled`, тот же
  компонент выбора дней/времени, что уже используется для «закрыто» (переиспользуется
  как composable, но с новыми `screeningWorkDaysMask`/`screeningStartMin`/`screeningEndMin`).
- Новая `ExpandableSection("Приветствия")`: три блока (Чешский/Русский/English), в каждом
  — переключатель источника (TTS-текст / файл), поле текста или кнопка загрузки файла
  (переиспользует существующий file-picker паттерн, которым уже загружается
  `amGreetingFile`). Чип выбора языка по умолчанию — CS предвыбран.

## Тесты

- `ScreeningPolicyTest` — юнит-тест чистой функции окна расписания (через полночь,
  границы), зеркалит существующий тест `ClosedState`/расписания.
- Возможно — тест на генерацию N повторов бипа (длина PCM пропорциональна количеству).

## Решения по ревью (2026-09-24)

1. **Скрининг важнее гарнитуры** (не наоборот, как было предположено изначально) — см.
   исправленный порядок маршрутизации выше. В рабочее время даже с подключённой
   гарнитурой (за рулём) владелец хочет видеть карточку и мочь ответить с телефона.
2. Подтверждено: владелец НЕ слышит абонента и не слышен абоненту, пока нет соединения
   (до нажатия «Принять») — реализация по плану (`ADJUST_MUTE` на всё время карточки).
3. Подтверждено: зуммер использует общий `amMaxMessageSec`, отдельный таймаут не нужен —
   «главное чтобы были гудки», точная длительность некритична.
